WHERE THE LINEAGE UNIT ENTERS (coordinator constraint, 2026-11-13)
 One array genome_code -> lineage id (softrec4.py universe()/set_lineage(); --lineage FILE (.npy by genome_code or
 parquet genome, lineage) and --lin-tag; outputs then under $RD/softrec/r4/lin_<tag>/; readings4.py --r4base reads
 them). Default = the GTDB genus array used since round 1. It decides (1) which genes a list excludes (own lineage, in
 the list expansion), (2) what L and the rank-weighted W count (distinct lineages other than the instance's), (3) the
 per-lineage best support kept for the instance graph (lever 1). The validated-family modules of round 2 inherit it
 through their lists. Taxonomy is otherwise used only for evaluation (Parvarchaeaceae ribosomal runs). No round-4
 step reads taxonomy to run beyond this array. Rerun with a lineage-free map: not done; $RD/lineagefree/ had
 candidate maps (groups/*.parquet) but no recommended map or report at 00:36 UTC when the configuration was chosen.

CAVEATS
- The odd-score deviation and the combination rule are mine; the rule admitted a lever (L2) whose odd gain was in
  the shortfall score only, which is why the post hoc L1 + L4 run is reported.
- zca10 whitening uses all 2.5 M sequences (as rounds 1-3). Critic thresholds use each fold's null; critic models never
  saw the scored genome's order.
- The support edge of an instance uses the best-ranked a' marking b''s slot; a worse-ranked a' forming a significant
  instance with the same b' is not used (affects which neighbour instance is linked, never L or W).
