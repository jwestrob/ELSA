3. BENCHMARK DESIGN (code/x05_modules.py; each module is OBSERVED domain content plus arrangement, never a system call)
 Elements: lanmodulin-like = 100-200 aa, >= 2 EF-hand loops (overlapping EF-hand Pfam rows merged), every loop-start gap
 within 4.5 aa of 24.5 x k (k 1-3), no other Pfam row (captures 37/49 lut lanM homologs); wide anchor = any 100-200 aa
 EF-hand protein; PQQ dehydrogenase = PQQ or PQQ_2 row, 500-700 aa (the notes' 'xoxF'). Rules: pair = neighbors, same
 strand (head-to-head for LanM|xoxF), gap <= 500 bp (<= 200 for CNNM, Metallophos); chain = <= 1 gene between, one
 strand, every gap <= 500 bp; window = within k genes, used only where the notes never tested strand.

 What a benchmark built from these would and would not test. It would test whether a method recovers and resolves
 conserved multi-gene units of 4-10 genes (mxa, pqq, H4MPT-type, Type A importer, lut, xoxF) and their nested sub-units
 across many lineages, against shift and translation chance. It would not test recovery inside one lineage (1-group
 families such as the complete lut cluster resolve at chance by construction), nor the notes' rejected LanM claims, which
 lut does not contain in numbers. It also treats co-orientation as the unit boundary, whereas the trees join conserved
 divergent flanks, so its resolved counts depend on that choice and should be reported beside the joined and separated rates.
