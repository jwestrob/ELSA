CHAIN
  shard.py (login node, single process, 55 s for all three in parallel) -> shards/shard_NNN.faa, shards.tsv,
  SHARDS.json. search_<c>.sbatch: one array task per shard, `aksha search --installed_hmms PFAM --cut_ga --prot_in
  <shard> --outdir search/shard_NNN --threads $SLURM_CPUS_ON_NODE`; checks shard size and Aksha 0.2.3 before, and
  output table + "Total sequences loaded" = shard size after; writes search/shard_NNN.done (JSON: rows, wall, CPU,
  RSS) or .failed. finish_<c>.sbatch -> merge.py (one process per shard + two for the source and concatenation
  hashes; pyarrow threads over the 24 CPUs): checks every shard file (SHA-256, headers), the partition (gid 0..N-1,
  no gap or overlap), source unchanged, concatenation = source, every .done marker (Aksha 0.2.3, loaded = shard
  proteins, rows = table rows), every hit inside its own shard, every model in meta/pfam_meta.tsv; writes
  PFAM.parquet (protein_id string = FASTA header, gid, accession, name, description, bitscore, evalue,
  dom_bitscore, c_evalue, i_evalue, hmm/ali/env coordinates; sorted by gid, env_from, accession),
  PFAM_summary.json, then STATUS last. Under flock on STATUS_ALL.lock, the finishing job that sees all three
  STATUS files appends the three final lines to $A/STATUS_ALL (lock logic tested on the login node).
  README_annotation.txt in each collection folder: shard size, Aksha version, Pfam 38.1, date, E-value note.
