half exists, so every primary output uses DPANN-chosen settings only. Predeclaration: predeclared.json (07:59 UTC; the
coordinator's two secondary items as amendment_0, 07:59), written before any word-method number. Notebook with UTC

   family-word outputs run with DPANN settings unchanged, the null-calibration rule transfers (tau* 8 for shared-gene-
   order counts and 10 for genome groups, the DPANN values), and both beat random placement:
     family words + phrases, shared-gene-order counts (P2): F1 .481, excess +.049 [+.014, +.084]

   Against the engine reference (best of 42 readings, F1 .750, excess +.184) both are BELOW: excess -.135 [-.173,
   -.097] (P2) and -.104 [-.138, -.069] (P1), F1 -.27 for both. Against the engine's single reading on the same tokens

   2026): the same round-0 pair statistic, unit and tau, assembled as runs with <= 2 intervening genes (CC2), scores

   predeclared expectation. The groups cover fewer query genes (47.5% vs 54.0%), so their random-placement control is

MATCHED PROTOCOL (what "matched" means)
Every output is a set of query-genome intervals, scored by model_scaling_20260913/code/evaluate_spacedust_queries
.evaluate unchanged: per region the single interval with the best gene-level F1; control = 200 rigid translations of
the region's membership pattern within its contig (seeded per region), scored against the same interval set; excess =
mean over regions of (F1 - mean control F1); 95% intervals from 10,000 bootstrap draws over regions; paired differences
by region bootstrap. Not matched, and the reason the control column matters: the engine reference is the union of 42
readings (3 gap rules x 14 support levels; 19,741 query intervals), native Spacedust the union of all its blocks
(63,756 query intervals), each word output one reading (~9,000-10,000 intervals).

CAVEATS
- P1's groups come from the CPU fallback (sampled estimate for pairs below 0.65, exact above), a declared deviation from
  exact per-genome maxima; if the exact GPU table is run later and the groups differ, P1 must be rescored on them.
- The stored ESM-C 300M vectors stand in for ESM++ small on the strength of identical weights and pooling; the bf16
  numerics of the two implementations were not compared on a sample (no GPU).
- source207 has no tuning half; every choice made after a number is labelled DEVELOPMENT.
- The engine reference and native Spacedust are unions of many readings, the word outputs single readings. The control
  absorbs part of that difference; the engine's own single reading (+.200) shows the union is not what makes the engine
  strong here.
- Query genomes carry no GTDB genus, so the engine counts each as its own lineage; the word method's units are derived
  from data (groups merge the 5 Streptomyces queries; shared-gene-order counts discount them by their S).
